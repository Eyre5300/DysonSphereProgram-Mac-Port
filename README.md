# 戴森球计划 Mac 版迁移工具

用自己购买的 Windows 版《戴森球计划》，在本机生成 macOS App。此仓库只提供 **MIT 许可的原创转换工具与平台适配代码**，不提供原游戏、恢复后的游戏代码、资产、游戏 App、存档或蓝图。

**状态：开发者预览。** 已在开发机完成转换与多批次实际游戏验证；新机器完整流程尚未验收。Steam 服务未接入，iPad/emu 部署未验证。

## 开始使用

1. 下载 Releases 中的 **纯工具 ZIP**，解压到本地目录。也可使用 GitHub 的 Code → Download ZIP。
2. 阅读 [用户操作指南](docs/用户操作指南.txt)，安装所列依赖并准备自己购买的完整 Windows 游戏文件。
3. 在工具目录启动 `start.command`。若下载后没有执行权限，在终端运行 `bash start.command`。
4. 向导会提示依赖、游戏/工具路径和本人 Unity 许可操作。完成后继续；可以暂停并恢复，日志和生成文件保存在另一个私有工作目录。
5. 构建完成后，按向导进行可选静音自检，再用自己的存档和蓝图试玩。构建成功不代表所有功能均无问题。

首次运行仍需人工准备依赖，不是现成游戏的一步安装器。工具不收集密码、不代替本人接受 Unity 许可，也不上传游戏或私人文件。

## 支持的输入与依赖

- 输入版本：Windows DSP **0.10.35.29104**，Steam depot `1366541`。游戏程序集 SHA-256 固定校验，未知版本会拒绝。
- Apple Silicon Mac、Python 3.12、Command Line Tools 或完整 Xcode。
- Unity **2022.3.62f3c1**、Mac 构建支持和已激活的适用许可。
- AssetRipper 2.0.0、SPIRV-Cross、vkd3d-compiler，以及 `requirements.txt` 中的 Python 库。

固定版本、上游来源、安装说明和 Steam 下载命令见 [依赖说明](docs/dependencies.txt) 与 [用户操作指南](docs/用户操作指南.txt)。工作目录使用本地非云同步磁盘，建议至少预留 50 GiB，实际峰值因输入与缓存而异。

## 验证与边界

开发机 M4 Pro、24 GB：79 项工具检查通过；当前源码包的发布边界检查通过。普通生产包完成原生 3840×2160 启动全屏、原设置切窗口/恢复、多 UI、保存重载和正常退出验证。

实际游戏批次覆盖基础生产/研究/无人机物流、10 份自有蓝图导入与模型预览、两份样例实际施工、星际曲速物流及途中保存、戴森球设计/涂装/火箭/太阳帆吸收、有限地面战斗和大存档。私有测试预置资源，不代表所有人工交互已验收。

最大测试存档约 4.87 GB，保留 159 工厂与 537 万实体；物理计费从此前约 40 GB 降至太空约 25.7–26.6 GB、繁忙地面约 27.8 GB。主要数组优化延后分配约 13.01 GB 原版全零尾部，编辑路径前恢复所需容量。不同计量不可直接相加；没有永久内存上限或全游戏 FPS 提升保证。历史性能对照固定 2752×2064、8×MSAA，不能直接推广至 4K。

以下尚未全面验收：新机器全流程、全部武器/太空战斗、复杂最大物流网络、多小时稳定性、全部偶发画面，以及 iPad/emu。当前路线是 Unity 重建 Mac；仅有 iOS 原生尺寸代码分支不等于 iPad 移植已完成。

详见 [行为差异](docs/behavior-parity.txt)、[性能证据与统计口径](docs/performance.txt)、[分享和安装区别](docs/publishing.txt)。不声称 Windows 完全等效或没有 bug。
