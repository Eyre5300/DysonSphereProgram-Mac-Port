Corrections in 44
1. GC mouse callback installation incorrectly treated a nil current callback
   and a nil installed callback as equal/owned. A first connection could thus
   install nothing. Require a nonnil installed callback for move, scroll and
   buttons, including ownership telemetry. The actual Pro callback slots and
   zero-delta delivery passed (probe mask 31); this is distinct from synthetic
   pointer packets.
2. Caps uses the explicit GCKeyboard key identity (USB usage 57) and a held
   edge counter, not an arbitrary button callback's pressed value. Other keys
   and repeat/hold/release cannot increment this counter in host tests. The
   game still uses its original warp predicate and default/custom bindings.
3. UICursor reads capture actually granted by UIKit, with focus/request gates;
   a request alone cannot enable captured free look. Original Tab and window
   policy is retained, including inventory before mecha on successive Esc.
4. Consecutive presses of one key retain ordered modifier snapshots in native
   and managed queues. Rapid Shift+R then R no longer overwrites the first
   pending modifier. PC Menu usage 101 is mapped to the existing KeyCode.Menu.
5. iPad render modes follow the actual display aspect ratio. On the tested
   Pro: 2752x2064, 1920x1440, 1600x1200, 1376x1032, 1280x960. The original
   preview/confirm/save path and startup selection preserve the chosen size.
   No permanent frame cap, MSAA reduction or other graphics change was added.

The trace showed approximately 120 rendered FPS, 60 logic UPS and two render
updates without a logic tick at the failing Escape. The unchanged Windows
VFInput delayedEscape -> GameMain.PausingInputLogic path pauses in that order,
before BuildTool_Click.EscLogic can consume the key. A private host replay of
those owned original methods reproduced both outcomes: with a logic tick in
between, the item is cancelled; without it, the item remains and pause opens.
This is a source-level Windows timing reproduction, not a Windows executable
hardware test. Do not call it a fixed port defect or an unrestricted input pass.
No closing-order change or permanent FPS limit was used to hide it.

A separate explicitly temporary 60-FPS reference batch passed all 39 keyboard
assertions and 10 display/callback/isolation checks, with normal exit and no
reported runtime errors. The previous VSync/FPS preferences were restored
afterwards. Both actual restart logs and the normal launch retained 1376x1032.
All 48 existing .dsv files were byte-identical after the batches. The test's
global achievement side effect was restored from the pre-test backup; options
differed only in width/height. Always protect global profile files as well as
redirecting test saves: GameConfig.gameSavePath does not redirect achievements.

Remaining equivalence limits
- Physical USB/Bluetooth/Universal Control Caps timing, unlimited relative
  travel, reconnect/background behavior and vendor-specific extra buttons need
  broader real-device coverage. Synthetic native injection cannot certify them.
- InputManager, CombineKey, rebinding UI and game consumers are source-reviewed;
  all custom binding combinations and every battle/editor/modal state were not
  dynamically retested. Earlier unaffected accepted batches remain historical
  evidence, not evidence that every combination was tested on 44.
- Cross-key sub-frame modifier overlap, OS-reserved shortcuts, keyboard layouts,
  IME composition, extreme macros/queue overflow and arbitrary focus changes
  are not exhaustively verified. Named Greater/Plus/SysReq retain the Unity
  fallback rather than guessed HID aliases; ordinary plus paths also accept
  the original Equals/KeypadPlus alternatives.
- iPadOS owns capture grants, system shortcuts and Files/iCloud presentation.
  Command remains separate from Windows Ctrl. File pickers use explicit import/
  export rather than unrestricted Windows paths. Dyson paste is validated on
  explicit paste to avoid passive clipboard permission reads. Existing Steam
  service and performance limits remain documented in behavior-parity.txt.
